# M28P5 聚合搜索「还是慢」：站点的命中先给缓存那份

- 状态：**已实现**（本机闸门全绿 + 新单测；上机待验）
- 时间：2026-10-12
- 触发：用户报「搜索影视的速度还是慢，后端可以考虑加从已经缓存的站点搜索」。

## 一、现在这条链慢在哪

聚合墙已经是**逐站回报**（先到先上墙，M28 首验之二十三），所以慢的不是「等全跑完」。剩下两块：

1. **同一部片总是重新从零打一遍**：从详情页退回来、换个入口再点 🔍、手滑重搜 ——
   每个站点都再发一次网络请求。上游站点里慢的（到 `site.timeout`）会让墙迟迟不满；
2. 结果**用完即弃**：没有任何一层替「刚才搜过的那个词」记着。

（宿主那边（js2p bundle）自己有一套 30 分钟的搜索缓存 —— 但那只对**完全相同的请求**生效，
我们这边每次重搜一样要等它把整条链重走一遍。）

## 二、修法：`SearchResultCache`（站点 + 关键词，只存命中）

| 文件 | 改动 |
| --- | --- |
| `CatVodUI/SearchResultCache.swift`（新） | actor：键 = 站点 + **归一化关键词**（去空白 + 小写）；只存**命中**（失败 / 零命中不存）；有效期 10 分钟；上限 400 条、超出丢最久没写过的 |
| `CatVodUI/AppModel+AggregateSearch.swift` | 首轮**先吐缓存那份**（一字节网络都不发就回报一次，墙面立刻有内容），实时那轮照旧跑：有新结果覆盖、**这次零命中就把缓存那份摘掉**、失败则留着缓存那份（一次连不上不该把墙清空） |
| `CatVodUI/AppModel(+Host).swift` | 换接口 / 宿主站点刷新时清空（站点集合都变了，旧命中没有意义） |

口径（写下来免得被「顺手统一」）：

- **不落盘**：搜索结果是「此刻这面墙」的东西，跨启动留存该走「首页缓存」那类有设置项的缓存；
- **不做设置项**：它只是加速，不是内容策略；
- **缓存键会归一化**：个别大小写敏感的上游会因此少命中一次缓存（照旧走实时搜索）—— 只是慢一点，不会错。

## 三、验证点（Mac / 模拟器）

1. `swift test --package-path Packages/CatVodUI`：新增 `SearchResultCacheTests`（存取 / 有效期 /
   归一化 / 上限淘汰 / 清空）；`AppModelIntegrationTests` 新增「先吐缓存那份」；
2. 上机：搜一部片 → 等墙出来 → 进详情再退回来 → **再搜同一个词**：墙面应当**立刻**出现上次那份
   （然后被实时结果刷新），不用再盯着转圈等；
3. 换个词搜：照旧（缓存对不上就正常走网络）。
