## 二、两条真毛病（都修了）

1. **起播那一下在拆正在出生的 VO**（`MpvEngine+VideoAreaSize.rebuildVideoOutput`）：
   `videoOutputMatches` 对「还没有 `osd-dimensions`」也给 `false` —— 而起播时 `loadfile` 刚下、
   mpv 正在建 VO（MoltenVK 要建整条 Vulkan 设备）：旧逻辑判定「尺寸不对」→ 等 500ms → 再等 300ms
   → 再等 500ms → **拆 VO 重建**（把刚建好的按掉）→ 再等 500ms —— 加起来秒级，全程黑屏。
   现在：**`osd-dimensions` 还没有 = VO 正在出生** → 先等它出来（上限 800ms），出生时尺寸就对的话
   一次都不重建；「片已经 `file-loaded` 过还看不到 VO」不算（那是 M28P6 的「VO 没建起来」，
   照旧走重建兜底，黑屏不能放着不管）。新增 `hasLoadedFile`（每次 load / teardown 归零）。
2. **时长被按帧写进 `@State`**（`PlaybackView` 的 `.timeChanged`）：位置那条早就节流了（0.1s 采样），
   但 `latestDuration = duration` 在**每条**事件（mpv 的 `time-pos` 是按帧来的）都写一遍 ——
   `@State` 写入不看值是否相等，于是整页 body 被按帧重建，播放中那点卡顿有它一份。
   现在：**变了才写**。

1. `swift test --package-path Packages/CatVodPlayer`（VO 出生期不动手 / 已 loaded 后照旧重试，
   两条用例按新语义更新 + 其余不变）、`swift test --package-path Packages/CatVodUI`；
2. 上机（mpv 内核最明显）：
   - 点播放：黑屏 + `0:00 / 0:00` 那一段应当**明显变短**（日志里起播不再出现
     `已重建 VO（… ms）`；若尺寸真不对才会出现，且只在 VO 出生之后）；
   - 正常速度播一段：卡顿应当变少（不再有每帧一次的整页重建）。
   - 若起播依然慢：发我 `grep -E '画面区|重建 VO|会话打开|第一帧'` 那几行（见 M28P6 第四节），
     那说明瓶颈在站点首字节 / mpv 初始化，不在我们这两处。
