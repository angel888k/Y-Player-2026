# M28P22 追剧封面：选集播放补齐 + 读取侧「站点缓存兜底」

- 状态：**已改**（本地闸门全绿）；上机验证随下次构建
- 时间：2026-10-12
- 触发：用户口径「播放历史的影视的封面要跟随站点优先从缓存加载」。

## 一、病灶（两处）

1. **写入口有洞**：`SitePlayEpisodeView` 的进度上下文档把封面写成 `picture: ""` ——
   **选集播放**（type=3 CatSpider / type=4 这两条异步取地址的链路）写进历史的记录
   在「播放历史」里**永远没有封面**（详情页点某一集播、精简视图就地播都走它）。
2. **读取侧没兜底**：记录里没封面（老记录）时，行上就只剩占位 —— 没有去站点缓存里找找看的回路。

## 二、改法

- **写入侧**：`SitePlayEpisodeView` 新增 `picture` 字段，三个构造点从详情页条目带
  `vod?.vodPic` 进来，落库时随元数据一起写。
- **读取侧**：`LibraryView` 重载时对「记录里没封面」的行，按「站点 + vodID」查**站点缓存**
  （`AppModel.cachedCoverURL(for:)` → 内存详情缓存；M28P10 起 js2p 详情也进缓存）——
  找到就上墙（这张图多半已经进过图片缓存，秒出），找不到照旧占位；**一字节网络都不发**。
- 「优先从缓存加载」的另一半是原有行为：行封面本来就由 `CachedImage` 走「内存 → 磁盘 → 网络」。

## 三、验证点

- 新用例 `cachedCoverFallsBackToSiteCache`（命中 / 未命中 / 站点不在当前接口 → nil）；
- 上机：详情页选一集直接播 → 退出到「追剧 → 播放历史」→ 该行应有封面；
  刚看过详情的旧记录进历史页也会补上封面（来自站点缓存，不发网络请求）。
