# M28P2 iOS 宿主启动（undici/WebAssembly）与发现页过期报错

- 状态：**已实现**（本地闸门全绿 + 新单测 + 本机把真 bundle 跑通；上机待验）
- 时间：2026-10-12
- 触发：用户报两条 ——「接口导入和站点加载有问题，有时站点加载是正常的也显示网络报错」，
  以及「同类型的接口导入显示宿主已经启动不能再次启动」（附两张截图）。

## 一、截图里的两个现象，四个根因

| 现象 | 根因 | 证据 |
| --- | --- | --- |
| 源地址页：宿主失败 + 落盘日志里 `ReferenceError: WebAssembly is not defined`（undici 栈） | iOS 版 libnode（nodejs-mobile 18.20.4）**没有 WebAssembly**，而 node 18 的全局 `fetch`/`Headers`/`Request`/`Response`/`FormData` 都挂在 undici 上：`fetch` 是包着 undici 的函数，其余四个是**惰性 getter**（fork 的 `lib/internal/process/pre_execution.js` 的 `setupFetch`）。bundle 的 `globalThis.X ||= 自家实现` 先**读**那些 getter，把 undici 拽进来；undici 的模块图在加载时（llhttp wasm）就抛错，宿主拿不到就绪行 | 用户落盘日志（`lazyllhttp → lib/… → lib/global.js → lib/fetch/index.js`）；本机复现：node 22 上模拟「无 WebAssembly」+ kstore 6.5 MB bundle，patch 前同栈必炸 |
| 点「重启宿主」→ 「每进程只允许一个 Node 实例；当前实例已启动但尚未拿到就绪行，无法再次启动」 | 原实现在「已启动但没就绪」时直接抛错；而 `node_start` 又**不可能重来** —— 就绪行只是来得晚也救不回来（第一次就绪等待 30 秒超时后，这条宿主在本进程里就报废了） | `NodeMobileRuntime.start()` 的旧 guard；用户截图 |
| （潜在）换 JS 接口 / `stopHost()` 后重载同一个 JS 接口 | `node_start` = `node::Start` → `InitializeNodeWithArgs` 的 `CHECK(!init_called.exchange(true))`：**第二次调用不是报错，是 abort 整个 App**。原代码允许在「换了脚本」时新建运行时再启动 | fork v18.20.4 的 `src/node.cc`（本机核对） |
| 发现页内容正常却挂着一条红色 `网络失败 … /home …`（换站点 / 下拉刷新之后出现） | 四个加载入口（首页 / 分类 / 翻页 / 分区）都是「发起 → await → 写状态」，没有代次判定：**旧请求晚到的失败会盖在新内容上**（也会把新内容盖回旧内容） | 代码审查：`errorText` 只由这几处写，await 之后无条件赋值 |

## 二、做法

| 文件 | 改动 |
| --- | --- |
| `CatVodNode/NodeMobileLaunchPlan.swift` | argv 固定加 `--no-experimental-fetch`（node 18 起支持；fork 的 `setupFetch` 认这个开关，直接不定义那一族全局） |
| `CatVodNode/NodePreloadScript.swift` | 预载兜底：`typeof WebAssembly === 'undefined'` 时把 `fetch`/`Headers`/`Request`/`Response`/`FormData` 摘掉 —— **只查属性描述符、不读取访问器**（读取本身就会触发 undici 加载）。`Blob` 来自 buffer，不动 |
| `CatVodNode/NodeMobileStartLedger.swift`（新） | 进程级启动账本（锁保护、平台无关、带单测）：`launch` / `reuse(port:)` / `blocked(existingScriptPath:)`。`NodeMobileRuntime.start()` 在调 `node_start` **之前**问账本：同脚本 → 接管地址（或交给仍在启动的原运行时）；换脚本 → 如实报「需要重启 App」 |
| `CatVodNode/NodeMobileRuntime.swift` | ①「已启动但没就绪」改为**续等**（`resumeStartedNode()`，先把 stdout 采集接回来 —— `startStdoutCapture()` 改成幂等）；② 就绪前退出 / 无法再启动的错误都带上「重启 App 才能再试」的出路；③ `markReady` 把实际端口记进账本 |
| `CatVodUI/DiscoverLayout.swift` | 新增 ``DiscoverLoadEpoch``（纯逻辑）：`begin()` 占号、`invalidate()` 作废在飞、`isCurrent(_:)` 判定 |
| `CatVodUI/HomeView.swift` + `HomeView+Data.swift` | 四个加载入口在**每个 await 之后的写**（`result` / `errorText` / `sections` / `selectedCategoryID` / `isLoading`）之前过代次判定；`invalidateContent()`（换站点 / 换接口）作废所有在飞加载 |

## 三、故意没做

- **不给 `/home` 超时加自动重试**：15 秒的上游超时是 bundle/上游的事，自动重试只会把
  「15 秒等到一条错误」变成「30 秒」；过期写入的判定已经能保证「后来的成功不会被旧的失败污染」，
  用户主动刷新/下拉仍是明确的恢复入口。
- **不在 iOS 上真重启宿主**（bootstrap 脚本 / 动态 require 接管 bundle）：那是另一套架构
  （bundle 自己导出 `{start, stop}` 且支持 `catServerFactory` 注入，理论上可做），
  本次只保证不 abort、如实报错。
- **不动 macOS 的进程方式**：那边每次启停是真进程，不需要账本，也不注入预载。

## 四、验证点（Mac / 模拟器）

1. `swift test --package-path Packages/CatVodNode`：新增 `NodeMobileStartLedgerTests`
   （首次 launch / 同脚本复用 / 换脚本 blocked / 启动前失败可还账 / 并发只有一个 launch）、
   `NodePreloadScriptTests` 新用例（整族摘除 + 描述符判定）、启动参数断言（`--no-experimental-fetch`）；
2. `swift test --package-path Packages/CatVodUI`：`DiscoverPageTests` 新增两条代次账用例；
3. 模拟器装 App → 导入 kstore 接口：宿主应就绪（源地址页「Node 宿主」不再是失败态）；
   落盘日志（`tmp/yplayer-node/yplayer-node.log`）里应出现
   `preload 摘掉 undici 背着的全局接口…` 且**没有** `FATAL unhandledRejection`；
4. 发现页：正常加载后不应再出现「内容在、红字也在」；下拉刷新失败时的红字会在下一次成功的
   加载后消失；换站点/换分类快速连点时列表不应被旧内容盖回；
5. 换到另一个 JS 接口加载：应看到「需要重启 App」的明确提示（而不是闪退或含糊的失败）。
