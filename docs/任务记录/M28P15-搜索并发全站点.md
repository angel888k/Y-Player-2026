# M28P15 搜索：并发搜接口的**所有**站点（并发 12 流水线 + 30 秒总预算）

- 状态：**已改**（本地闸门全绿）；上机结果等用户确认
- 时间：2026-10-12
- 触发：用户问「影视的搜索是并发搜索接口的所有站点吗，请扫描代码修复」——
  口径就是「并发搜索接口的**所有**站点」；此前 M28P11 的收口（首轮截 12、补搜最多 3 波、
  够 3 个站点命中就停）**不满足**这个口径（用户看到的墙上常常只有两个站点的结果）。

## 一、改了什么

- `AggregateSearchRules.targets(sites:)` 不再截断：索引站点（`indexs == 1`）排最前，
  **其余站点照站点清单顺序排在后面** —— 范围就是全部可搜站点；
- 删掉收口那三个概念（`firstRoundLimit` / `fallbackWaveLimit` / `enoughHitSites`）与
  随之死掉的 `didFallBackToAllSites`；
- 新增 `concurrentLimit = 12`：与传输层每 host 12 条连接对齐（`siteSessionConfiguration`）；
- 新增 `searchTimeLimit = 30s` 总预算（纯函数 `shouldStartAnotherSite(now:deadline:)` 有单测）：
  到点后不再开新站点、在飞的等它们回来 —— 保证一轮搜索总能收尾；
- `AppModel.searchAcrossSites`：**一条流水线**搜全部站点（一个回来就补下一个，不是「一批等一批」
  ——否则一个 15 秒超时的慢站点会把这一批的空位全堵住）；`searchedKeys` 初值 = 全部可搜站点
  （进度分母 = 全部）；
- 新增 `SearchTrace`（category `search`）：一轮结束记一条
  「聚合搜索：站点 N · 已回 M · 命中 K · 墙钟 T ms」——`grep 聚合搜索` 即可核对口径。

## 二、实测（本机直跑主接口宿主 kstore，关键词「哪吒」，`Tools/out/probe-all-search.txt`）

- 可搜站点 95 个（96 个里 1 个永久禁搜）；并发 12 **全部开搜：未开搜 0**（30 秒预算没被用上，
  队列 ~9 秒就排空）；
- 总墙钟 **24.3s**（尾部慢站点 15 秒超时那一档拖的）；**首个命中 0.6s 上墙**；
- **48 个站点命中**（旧收口策略只会保留首轮 12 个里命中的那几个，之后就不再搜了）；
- 探测脚本自身局限：4 个中文 key 的站点（少儿教育/小学课堂/…) 因 Python 侧编码限制没真发出去，
  口径不受影响（App 里照旧按 URL 发）。

## 三、验证点

1. `swift test --package-path Packages/CatVodUI`：`targets` 不截断 / 顺序（索引在前）、
   总预算纯函数、归位等用例；
2. 上机：随便搜一个词 —— 日志应出现
   `聚合搜索：站点 95 · 已回 95 · 命中 ~48 · 墙钟 ~24xxxms`；
3. 左栏「全部 (命中/参与)」的参与数 = 该接口的全部可搜站点数；墙面**边搜边出**内容。
