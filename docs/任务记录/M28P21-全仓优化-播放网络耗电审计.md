# M28P21 全仓优化 · 第三批：播放器 / 网络 / 耗电审计（+ 时间戳 formatter 复用）

- 状态：**已改**（本地闸门全绿）；审计结论如下
- 时间：2026-10-12
- 触发：同 M28P19/20 的全仓扫描，这批盯「播放器内核参数 / 网络连接 / 耗电」。

## 一、这轮改掉的

- `DiagnosticsReport.timestamp` 每次调用现建 `DateFormatter` —— 它在接口页**每次渲染**与诊断报告
  组装里会被反复调。改成建一次复用（只读即线程安全，口径不变）。

## 二、审计过、**不动**的（附理由，防止以后被「顺手改」）

- **播放器（mpv）**：只设渲染四项（`wid` / `vo=gpu-next` / `gpu-api=vulkan` / `gpu-context=moltenvk`）
  与 `hwdec` —— 有意保持最小集；事件循环 `waitEvent(0.05)`（mpv 惯用档）；
  `cache` / `demuxer-*` 用默认（`cache=auto` 对网络流已启用，改大小需要上机 A/B，留作按体感调）。
- **播放器（系统内核）**：就绪轮询 100ms 只到「就绪 / 失败」为止（≤20s），不是常驻；
  缓冲策略用 AVPlayer 默认（`automaticallyWaitsToMinimizeStalling` 默认开，正合流媒体）。
- **帧级渲染**：弹幕层 / 字幕层 `TimelineView(.animation(1/60, paused: 时钟没跑))` —— **暂停即停表**；
  覆盖层靠 `PlaybackClock` 外推（0.1s 采样），不是每个内核事件全页重建（M28 收尾已做）。
- **网络**：站点每 host 24、图片每 host 8（都经过实测调过）；代理会话 `copy()` 继承同一套配置
  （并发 / 超时 / 缓存策略一致）；宿主探活是**按需**（进接口页 / 点按钮），没有轮询；
  站点会话 `URLSession` 由 `AppModel` 缓存复用，不是每次请求新建。
- **存储 / 下载**：GRDB 单队列（WAL 默认）；下载按块写文件 + 进度按步上报，无 `synchronize` 全量刷盘。
- **UI 循环**：全仓无 `Timer`；`LiveClock` 按整分钟；帧探针只在**模拟器**编译；
  `CachedImage` 刻意不用 `GeometryReader`（懒容器里的已知代价）；
  TMDB 头图轮播按间隔 sleep、随视图取消。
