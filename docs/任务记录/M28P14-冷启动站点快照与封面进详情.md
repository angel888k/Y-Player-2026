# M28P14 冷启动先摆站点快照 · 点封面先进详情页标题

- 状态：**已改**（本地闸门全绿）；上机观感等用户确认
- 时间：2026-10-12
- 触发：用户问「已经导入过接口的情况下，冷启动的站点加载是优先缓存吗」+「点击封面后的加载速度也可以再快点」。

## 一、回答那个问题：**原来不是**优先缓存（站点清单一直要等宿主）

JS 源（js2p）的站点清单不在配置里，只在宿主里（`GET /full-config`）—— 而宿主启动要几秒。
「首页缓存」是按站点 key 存的、本身是缓存的，可**没有站点就没有发现页**，缓存的内容也摆不出来：
所以冷启动的实际体验是「对着转圈等宿主」。其它源（JSON 配置）的站点在配置里，本来就有，不受影响。

改法（`HostSiteSnapshotStore`，M28P14）：

1. 每次 `refreshHost` 成功拿到站点清单后，**落一份快照**（`host-sites-<md5(scriptURL)>.json`，
   含清单 + 那次宿主地址前缀 + 被禁用的站点数）；
2. `AppModel.load()` 里在**起宿主之前**先读回快照并摆出来（`publishCachedHostSites`），
   顺手自增 `siteCatalogRevision` → 发现页立刻用「首页缓存」把那个站点的内容渲染出来
   （一字节网络都不用），站点切换器里也有站点了；
3. 宿主就绪后 `refreshHost` 用**新清单整体替换**（端口随之对齐）。

已知取舍（写在 `HostSiteSnapshotStore` 的注释里）：快照里 JS 站点的 `api` 带着**上次的宿主端口**
（首选 9988，被占才顺延）——端口多数时候不变；变了的话，「宿主起来之前那几秒里点进去会失败」，
起来之后就没这回事。比「整页转圈」划算，这个取舍是有意的。

## 二、点封面：标题先用列表带过来的名字

详情页要等 `/detail` 回来才有片名 —— 而列表卡片上本来就有这个名字。现在 `VodDetailView` 多收一个
`preview: VodItem?`（发现页网格与搜索墙两处传入），标题按「详情的片名 > 列表带过来的片名 > 详情」取：
点进去立刻能看到片名，剧集区仍是「加载中…」，不再是「详情 + 空白」。

首访详情页的耗时 = 一次站点 `/detail` 往返（JS 站点还要跑一遍站点 JS），这是站点自己的账；
**重复进同一个详情页**早就走 5 分钟缓存（M28P10），是秒开的。

## 三、验证点

1. `swift test --package-path Packages/CatVodUI`（未动数据口径，全绿即可）；
2. 上机：
   - 冷启动（已导入过接口）：发现页应当**立刻**出现站点名与上次的内容（宿主还在后台起），
     不再对着转圈；宿主起来后内容照旧刷新；
   - 点封面：进详情页立刻能看到片名；返回再点同一个封面应当秒开（缓存）。
