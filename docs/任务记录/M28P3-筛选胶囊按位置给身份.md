# M28P3 筛选胶囊「点不了」：`ForEach` 的身份不能拿上游数据当

- 状态：**已修**（本机闸门全绿 + 新单测；上机待验）
- 时间：2026-10-12
- 触发：用户报「部分系统版本，发现页，站点的时间 / 字母 / 排序（筛选）点不了」。

## 一、先证明协议没坏（不然后面会修错层）

本机用真宿主把筛选链路跑了一遍（kstore `/cat/` 6.5 MB bundle，node 22 + 模拟「无 WebAssembly」，
宿主链路见 M28P2）：同一分类带上 `filters` 的请求会拿到**不同**列表 ——

| 站点 | 无筛选首条 | 带筛选首条 | 结论 |
| --- | --- | --- | --- |
| 闪电 `{"year":"/year/2020"}` | 年会不能停！2 | 馗降：粽邪2 | 生效 |
| 闪电 `{"letter":"/letter/A"}` | 年会不能停！2 | 澳门风云3 | 生效 |
| 蜡笔 `{"year":"/year/2019"}` | 午夜凶铃：凶铃再现 | 飞驰人生 | 生效 |
| 观影 `{"sort":"score"}` | 差点死 | 拯救生命演唱会 | 生效 |

原始证据 `Tools/out/filters-effect.txt`（本机脚本产出，不入库）。也就是说「值 → 宿主 → 上游」是通的，
问题在界面层。

## 二、根因：`ForEach` 拿 `v` / `key` 当身份，而上游的 `v` 不保证唯一

`VodFilterValue.id` 是 `v`（提交值）；真实接口的数据里 `v` 会重复（宿主自己的站点元数据缓存，
`data/wexfnwconfig.json` 的 `runtime/siteMetaCache`）：

- **蜡笔（labi）剧情行：两个「恐怖」，`v` 都是 `/class/%E6%81%90%E6%80%96`**；
- 花卷（huajuan）剧情行同上，另外首项「全部」的 `v` 是**空串**；
- 闪电 / 观影多处「全部」也是空 `v`。

`ForEach(row.values)`（id = `v`）一旦撞 id，SwiftUI 的行为**未定义**（会打
"The ID … occurs multiple times within the collection" 警告）：轻则选中态错位，重则那一行点不动，
而且**各系统版本的表现不一致** —— 与用户报的「部分系统版本」对得上。
行也一样：`ForEach(rows)` 的 id 是 `row.key`，上游重复 key 就同样会撞。

## 三、修法

``DiscoverFilterStrip``：行与胶囊的 `ForEach` **一律按位置给身份**
（`ForEach(Array(x.enumerated()), id: \.offset)`）——身份不再依赖上游数据的唯一性；
数据重复照原样显示（对齐参考实现：上游给几条画几条），点哪条提交哪条的 `v`。
仓库里 `ChangeSourceView` / `InterfaceManagementView` 早就是这种写法。

## 四、验证点（Mac）

1. `swift test --package-path Packages/CatVodUI`：`DiscoverPageTests` 新增
   「上游给重复的 v（恐怖×2）/ 空 v（全部）、甚至重复的行也要能构造」；
2. 上机：进「蜡笔」「花卷」（有重复值的站点）→ 选「电影」→ 点「全部剧情」行里**第二个「恐怖」**，
   以及「全部时间 / 字母 / 排序」那几行 —— 都应能选中并刷新列表；
3. 之前报「点不了」的那个系统版本上重点复测。若仍点不动，需要三样东西才能继续定位：
   **站点名 + 系统版本 + 点按反馈（完全没反应 / 选中了但列表不变）**。
