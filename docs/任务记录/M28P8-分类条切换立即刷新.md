# M28P8 发现页「分类条点了不是立马刷新」：换分类当场清内容 + 翻页回来核对上下文

- 状态：**已改**（本地闸门全绿 + 新增一条纯函数用例）；上机观感等用户确认
- 时间：2026-10-12
- 触发：用户报「导入接口后发现页各站点的分类条点击切换后不是立马刷新」。

## 一、两条真因（都出在点击那一刻）

1. **旧片单会一直摆到新请求回来**：`selectCategory` 只改 `selectedCategoryID` / `extend` / `page`，
   `result` 不动 —— 页面要等网络回来才换内容，中间除了分类条的字重变化没有任何反馈
   （`isLoading` 只在列表为空时才顶用：`contentBody` 的空态）。表现就是「点了看着像没反应」。
2. **底部那块会当场再发一次翻页，把这轮切换顶掉**（更要命的一条）：
   `loadMoreFooter` 的 `.task(id: loadMoreTrigger)` 键是「页码 + 条数」。用户滑过几页再点分类时
   `page` 从 3 拨回 1、列表没变 → 键变了 → 那个 `.task` 当场跑 `loadMore()`：
   - 它先取一个**更晚的代次号**（`beginDiscoverLoad()`）→ 真正的分类加载成了「过期写入」，整段被丢；
   - 又把**新分类的第 2 页**追加进**旧分类**的列表（`appendPage`）——
     用户看到的就是「点了没切换，反而多出一截」。

## 二、改动

- `DiscoverCategorySwitch.clearedContent(_:)`（`DiscoverLayout.swift`，纯函数有单测）：
  换分类 / 改筛选时把内容清成「等待新分类」的样子 —— 列表清空、总页数归零；
  **分类条与筛选数据留着**（分类条马上还要点；筛选按分类 ID 为键，不吃旧值）。
- `HomeView+Data.beginCategorySwitch()`：`selectCategory` / `applyFilter` 都走它 ——
  ① 代次作废（在飞的旧加载一律不写）；② 内容清空 + `isLoading = true`（当场「加载中…」）；
  ③ `page` 回 1、`reachedEnd` 归位。列表一空，底部那块 `.task` 整块不在树上，岔路 2 自然没了。
- `HomeView+Data.loadMore()`：记下这次翻页的上下文（分类 + 筛选），**写回前核对**
  （`isSameContentContext`）—— 中途换过分类 / 改过筛选的返回直接丢弃：不追加、也不报错。
- `loadCategory()`：代次 / 加载态 / `defer` 提到参数判空之前 —— 早退也要把加载态收干净
  （`beginCategorySwitch` 会先把 `isLoading` 拨到 true，不收拾就会一直转圈）。

## 三、验证点

1. `swift test --package-path Packages/CatVodUI`：新增
   「切换分类 / 筛选：当场清内容，但分类条与筛选数据要留着（「点了不是立马刷新」的锚点）」；
2. 上机（纵向展示）：滑过两三页 → 点另一个分类：
   - 点下去**当场**变成「加载中…」＋转圈（不再摆着上一分类的片单）；
   - 新分类第一页回来后才铺网格；**不会**把新分类的第 2 页混进旧列表；
   - 筛选胶囊换一个值同理。

## 四、没动的

横向展示（分区那一套）里点分类胶囊仍旧只准备纵向那份数据 —— 那边的入口设计是分区标题上的
「>」（切到纵向展示看整个分类），这次不夹带改产品行为；真要改另开一笔。
