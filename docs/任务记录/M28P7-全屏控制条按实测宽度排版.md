# M28P7 全屏控制条「按钮排版不行」：宽 / 窄两套版式改成**按实测尺寸挑**，徽标不许折行

- 状态：**已改**（本地闸门全绿）；上机后的观感等用户确认 —— 见第四节「如果还错位」
- 时间：2026-10-12
- 触发：用户报「部分系统版本，全屏播放器的按钮排版不行，例如视频码率格式等显示错位，选集按钮错位」。

## 一、先把底排这条链复核一遍（两处会「散」的构造）

| 症状（用户口径） | 现在的构造 | 为什么会散 |
| --- | --- | --- |
| 按钮排版不行 / 选集按钮错位 | 底排「宽版（文字）/ 窄版（图标）」按**估出来的宽度线**切（`barCompactWidth = 560`；宽版按 iOS 系统字体量了 ~541pt） | 估的账只对「iOS + 默认字号 + `Menu` 在 iOS 的样子」成立 —— 系统字体换版本、用户开大字号、macOS 上 `Menu` 自带下拉按钮外壳（比 iOS 标签宽一截），任何一处变一点，宽版就装不下：文字被压扁 / 折行 / 行内间距散开。**「部分系统版本」正是这条估算的锅。** |
| 码率格式等显示错位 | 参数徽标行（`HW HDR H265 4K 25FPS 5.6 Mbps`）一个 `HStack`，每个 `Text` **没设** `lineLimit` | 徽标里有「5.6 Mbps」这种带空格的文本 —— 条一窄，`Text` 默认**允许折行**：它先被折成两行，整排的高度与基线全散（看着就是「码率格式错位」）。 |

排除了的：按钮本身的尺寸（图标 30×30、文字 label 高 30）与行内间距都是明账，不是散的原因；
控制条也不是按「画面显示矩形」摆的（它铺在画面区整层上）—— 与视频宽高比无关。

## 二、改动

1. **新增 `Platform/AdaptiveFit.swift`：`AdaptiveFitRow`** —— 「装得下就上宽版」的版本自适应容器：

   | 系统 | 实现 |
   | --- | --- |
   | iOS 16+ / macOS 13+ | 原生 `ViewThatFits(in: .horizontal)`：**量一遍**，挑第一版真装得下的 |
   | iOS 15 | 没有这个 API —— 回落「按可用宽度对 `threshold`」（与改之前一致） |

   与 `AdaptiveTap` / `AdaptiveZoom` / `AdaptiveNavigation` 同一套做法：版本分支集中在基础件里。

2. **`PlaybackView+Controls.swift`：动作行改走 `AdaptiveFitRow`** —— 宽版（文字排）实测装得下才用，
   否则换图标版（动作与菜单内容一模一样）。`barCompactWidth` 只剩两处用处：iOS 15 的回落判据、
   顶排图标的间距档。极简版（竖屏精简视图）与原来完全一致：播放 / 暂停 + 右下角全屏。

3. **参数徽标行：每条 `lineLimit(1)` + `minimumScaleFactor(0.8)`，整排 `frame(maxWidth: .infinity,
   alignment: .leading)`** —— 装不下先等比缩、再行尾截：**不折行、不越界**，整排钉在控制条最左边。

## 三、验证点（Mac）

1. `swift test --package-path Packages/CatVodUI`（本轮只动视图构造，行为性纯函数都有旧用例兜着）；
2. 上机：全屏播放器
   - 竖屏（宽 < 560）：底排应当仍是**图标版**（与改之前一致）；
   - 横屏 / iPad / macOS 窗口：宽版装得下就上文字排；把 **macOS 窗口往窄里拖**（500–600pt 这一带）
     应当**自动换图标版**，而不是把「播放器 / 字幕 / …」压扁；
   - 参数徽标：窄条下**不折行**（宁可缩一点 / 行尾截）。

## 四、如果还错位：发我一张全屏截图 + 哪台系统版本

这条改动治的是「行溢出 / 折行」这一类。如果截图里是别的东西（比如某个平台把 `Menu` 画成了
另一种外壳、或面板工具栏在窄面板里挤），看截图就能钉死 —— 到时候按截图改那一处，不再猜。
